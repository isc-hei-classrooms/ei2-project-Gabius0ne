Convention temporelle

Trois dates coexistent dans le code, à ne pas confondre :

target_date
Le jour à prédire. C'est J+1 dans la convention métier.
day_j
target_date − 1 jour. Jour de soumission, à 11h UTC+1. Données live partielles dispo.
day_jm1
target_date − 2 jours. Dernière journée complète disponible à la soumission.

Point à corriger dans la doc interne : le suffixe jm1 dans les noms de features (ex. load_jm1, rmet_jm1) désigne en réalité J−2 par rapport à la cible. La convention est relative au jour de soumission J. Source de confusion fréquente lors de l'analyse SHAP.

Mélange de timezones : les groupes A/B/C utilisent l'heure locale Europe/Zurich (suffixe _hHH), le groupe D utilise UTC (suffixe _tHH). Décalage de 1h ou 2h selon la saison.
